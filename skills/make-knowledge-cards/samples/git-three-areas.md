# Git 三大区域：工作区、暂存区、仓库

很多 Git 新手一上来就被 `git add`、`git commit`、`git push` 三个命令搞晕，根源是没分清 Git 在脑子里其实有"三个房间"。

## 三个区域分别是什么

- **工作区（Working Directory）**：你电脑里能直接看到的那个项目文件夹，文件被改了就直接体现在这里。
- **暂存区（Staging Area / Index）**：一个"准备打包"的中间区，你可以挑选这次想提交哪些改动。
- **仓库（Repository / .git）**：Git 真正存历史的地方，每次 `commit` 都会在这里留下一张不可变的快照。

## 文件在三个区域之间的流转

1. 编辑文件 → 改动落在**工作区**。
2. `git add <file>` → 把指定文件的当前快照放进**暂存区**。
3. `git commit -m "..."` → 把暂存区里的所有内容打包成一次提交，存入**仓库**。
4. `git push` → 把本地仓库的提交同步到远程仓库（GitHub 等）。

## 为什么需要暂存区

暂存区让"我这次想提交什么"和"我手头在改什么"解耦。你可以在工作区里改了一堆东西，但只挑选其中相关的几条放进暂存区，凑成一次主题清晰的提交。这让代码历史更容易阅读，也让 `git diff --staged` 这种"预览本次提交"的能力成为可能。

## 三个有用的状态查看命令

- `git status`：告诉你哪些文件在工作区/暂存区分别被改过、还没提交。
- `git diff`：看工作区相对暂存区的差异。
- `git diff --staged`：看暂存区相对上次提交的差异（即"这次 commit 会包含啥"）。

理解这三个区域之后，Git 不再是玄学，而是一套清晰的搬运流水线。
